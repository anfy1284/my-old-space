## 2. БАЗОВЫЕ КЛАССЫ (UI_classes.js)

### UIObject
Базовый класс всех визуальных компонентов. Свойства: `x, y, width, height, z, element`.

### Form (extends UIObject)
Окно с заголовком, кнопками управления (свернуть, развернуть, закрыть), drag/resize.
- `close()` → вызывает `this.destroy()`, удаляет DOM, диспатчит `form-destroyed`
- `destroy()` → уничтожает дочерние контролы
- `doAction(action, params)` → **Системная обработка действий**. Если `params.isStandard === true`, действие обрабатывается непосредственно в базовом классе `Form` (например, `recordOpen`, `recordAdd`, `recordDelete`, `cancel`). В противном случае (или если действие не распознано как стандартное), оно делегируется в `instance.onAction()`.

### DataForm (extends Form)
Базовый класс для форм с автоматическим рендерингом из JSON layout.

**Свойства:**
| Свойство | Назначение |
|---|---|
| `controlsMap` | Map всех созданных контролов `{name: control}` |
| `_dataMap` | Данные формы `{fieldName: {name, value, ...}}` |
| `_datasetId` | ID серверного датасета (хранит таблицу + ID записи) |
| `_modified` | Флаг изменения данных. При `true` — заголовок с ` *` |
| `_originalTitle` | Заголовок формы без суффикса ` *` |
| `_closing` | Защита от рекурсивного закрытия (guard) |
| `_currentRecord` | Текущая выбранная запись (setter обновляет контролы) |
| `table` | Ссылка на первую `DynamicTable` (устанавливается автоматически в `renderItem`) |

**Ключевые методы:**
| Метод | Назначение |
|---|---|
| `setModified(bool)` | Устанавливает `_modified`, добавляет/убирает ` *` из заголовка |
| `setTitle(title)` | Переопределён: сохраняет `_originalTitle`, учитывает `_modified` |
| `close()` | Переопределён: если `_modified`, спрашивает "Сохранить?" через `showConfirm` |
| `doAction('save')` | Вызывает `collectData()` → `applyChanges()` → сбрасывает `_modified` |
| `doAction('cancel')` | Вызывает `this.close()` (с диалогом сохранения если `_modified`) |
| `collectData()` | Обходит `controlsMap`, собирает `{field: value}` |
| `applyChanges(data)` | Отправляет `{datasetId, changes}` на сервер |
| `renderItem(item)` | Рендерит контрол по JSON-описанию, подключает dirty-tracking |

**Жизненный цикл:**
1. `MySpace.open('uniRecordForm', { tableName, recordID })` → создаёт экземпляр DataForm
2. `DataForm.Draw()` → `loadLayout()` → `getLayoutWithData()` → рендерит контролы
3. Пользователь редактирует → контролы вызывают `setModified(true)` → заголовок получает ` *`
4. При закрытии (X/ESC/Отмена): если `_modified` → `showConfirm("Сохранить?")` → "Да"=save+close, "Нет"=close
5. `Form.close()` → диспатчит `form-destroyed` → слушатель в DynamicTable вызывает `refresh()`

**Dirty Tracking (отслеживание изменений):**
Все контролы формы при изменении вызывают `formSelf.setModified(true)` (где `formSelf` — замыкание на DataForm):
| Контрол | Событие |
|---|---|
| TextBox, MultilineTextBox | `input` на `ctrl.element` |
| emunList (ComboBox listMode) | `input` на `ctrl.element` |
| recordSelector (TextBox + кнопка "...") | `input` на `ctrl.element` |
| CheckBox | `change` на `cb.element` |

### Group (extends UIObject)
Контейнер для логической группировки элементов (отрисовывается как `fieldset` с `legend`).
- `children` (Array): Список дочерних `UIObject`.
- `Draw()`: **Автоматически** проходит по массиву `this.children` и вызывает `child.Draw(this.element)` для каждого. Это основной способ создания вложенных структур.

### Table (extends UIObject)
Базовая таблица. Поддерживает заголовки, сортировку и рендеринг строк.

- `showToolbar` (bool): Если `true`, в начале таблицы отрисовывается панель действий.
- `isTabularSection` (bool, default `false`): Автоматически определяется в `Draw()` из `appForm._dataMap[dataKey].tabularSection`. Если `true` — таблица является табличной частью (ТЧ): тулбар самостоятельно обрабатывает добавление/удаление строк без делегирования в `DataForm.doAction`.

**`doToolbarAction(action)`:**  
Обрабатывает действие тулбара. Если `isTabularSection === true`:
- `recordAdd` → добавляет пустую строку в массив данных ТЧ и вызывает ре-рендер.
- `recordDelete` → удаляет активную строку из данных ТЧ.
- Возвращает `true` если обработано (ТЧ), `false` если нужно делегировать дальше.

Если `isTabularSection === false` — возвращает `false`, и `appForm.doAction(action, { isStandard: true })` продолжает цепочку.

**Тулбар (`Draw()`):**  
Строится напрямую через `new Button()` → `btn.Draw(toolbarContainer)` для каждой кнопки действия. Контейнер: `<div class="ui-toolbar">`. Каждый `btn.onClick` вызывает `table.doToolbarAction(action)`, и если `false` — делегирует в `appForm.doAction(action, { isStandard: true })`.

> **CRITICAL:** Никогда не использовать `appForm.renderItem(toolbarLayout)` для тулбара класса Table — `renderItem` теряет ссылку на экземпляр таблицы и лишает кнопки доступа к `doToolbarAction`. Кнопки тулбара Table ОБЯЗАНЫ создаваться через `new Button()`, а НЕ через `document.createElement('button')` — иначе они получают неправильный цвет и стиль.

### DynamicTable (extends Table)
Таблица с серверной подгрузкой данных по частям, SSE-обновлениями и виртуальным скроллом.

**Подход: pre-allocated rows (все строки в DOM)**  
Все `<tr>` создаются в DOM сразу при получении `totalRows` с сервера. Строки пустые (placeholder) до момента попадания в вьюпорт. Скроллбар браузера отражает полный датасет без какой-либо математики позиционирования.

**Ключевые свойства:**

| Свойство | Назначение |
|---|---|
| `totalRows` | Общее число строк датасета (от сервера) |
| `dataCache` | Кэш загруженных строк `{ globalIndex: record }` |
| `_rowElements` | Массив всех `<tr>` элементов, индекс = globalIndex |
| `_activeRowIndex` | **Глобальный** индекс активной строки (= globalIndex) |
| `firstVisibleRow` | Глобальный индекс первой видимой строки (для запроса следующей страницы) |
| `bufferRows` | Число строк-буфера выше и ниже вьюпорта (по умолчанию 10) |
| `rowHeight` | Высота строки в px (по умолчанию 25) |
| `editSessionId` | ID редакторской сессии (возвращает сервер) |

**Ключевые методы:**

| Метод | Назначение |
|---|---|
| `buildBody()` | Создаёт обычную `<table>` с пустым `<tbody>`, сохраняет `_mainTbody`, `_dtBcolgroup` |
| `_allocateRows()` | Создаёт/дополняет `_rowElements[]` до `totalRows` TR-плейсхолдеров |
| `_fillRow(globalIndex)` | Заполняет TR ячейками из `dataCache[globalIndex]`, ставит `tr._dtFilled = true` |
| `_emptyRow(tr)` | Сбрасывает TR в placeholder (`_dtFilled = false`) |
| `_fillVisibleRows()` | Заполняет все кешированные строки в диапазоне scrollTop±buffer |
| `_resetFilledRows()` | Сбрасывает все `_dtFilled` флаги (O(N), без DOM) — вызывается при `refresh()` |
| `_onScroll()` | Сначала `_fillVisibleRows()`, потом запрашивает у сервера недостающие строки |
| `activateRow(globalIndex)` | O(1): снимает класс `active` с предыдущего TR, ставит на `_rowElements[globalIndex]` |
| `deactivateRow()` | Снимает `active`, очищает `_docKeyHandler` |
| `updateAllRowsReadOnly()` | Итерирует только видимый диапазон (не все N строк) |
| `onSelectOrOpen(globalIndex)` | Прямой `dataCache[globalIndex]` → открывает uniRecordForm или срабатывает selectMode |
| `refresh()` | `dataCache = {}` + `_resetFilledRows()` + `loadData()` |
| `loadData(firstRow)` | Загружает страницу данных, после получения: `_allocateRows()` + `_fillVisibleRows()` |

**Важно:**  
`_activeRowIndex` — это **глобальный** индекс (= позиция в `_rowElements[]` = ключ в `dataCache`).  
Формула `firstVisibleRow + _activeRowIndex` **не используется** — все операции работают непосредственно с globalIndex.

**SSE:**  
При мутации данных на сервере приходит SSE-событие → `dataCache = {}` + `refresh()` на всех подписчиках.

**`destroy()`** очищает: `_scrollDebounce`, `_scrollHandler`, `_resizeObserver`, `_docKeyHandler`, `_rowElements`, SSE EventSource.

## 3. ПРОЦЕСС СОЗДАНИЯ ПРИЛОЖЕНИЙ (APPS)

Любое новое приложение должно быть зарегистрировано и оформлено по следующим правилам:

### Регистрация (ОБЯЗАТЕЛЬНО)
Чтобы сервер (loadApps) увидел приложение, его необходимо добавить в `drive_forms/apps.json`:
```json
{
  "name": "myAppName",
  "path": "/myAppName"
}
```

### Конфигурация (config.json)
- `autoStart: true` — скрипт client.js будет загружен в браузер при старте.
- `access: ["admin", "user", "public"]` — определяет доступность приложения.

### Клиентская часть (resources/public/client.js)
Должна использовать паттерн `MySpace.register` с методом `createInstance`. Пример:
```javascript
MySpace.register("myApp", {
    config: { allowMultipleInstances: true },
    createInstance: async function(params) {
        const appForm = new DataForm("myApp");
        const instance = {
            onOpen: async (p) => { await appForm.Draw(); },
            onAction: (action, p) => { /* логика */ }
        };
        appForm.instance = instance;
        await instance.onOpen(params);
        return instance;
    }
});
```

### Взаимодействие doAction (АНТИ-РЕКУРСИЯ)
Фреймворк использует каскадную обработку: `Form.doAction` → `instance.onAction`.
**КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** в `instance.onAction` вызывать `appForm.doAction`, если вы не обрабатываете действие сами. Это создаёт бесконечную петлю. Если приложение не знает как обработать действие — оно должно просто выйти из функции (вернуть `false`/`undefined`). Фреймворк сам найдет стандартную реализацию.

### Стандартные контролы
- **Button:** Обычная кнопка. Использует `action` и `params` для вызова `doAction` через `onClick`.
- **TextBox, CheckBox, ComboBox (emunList):** Стандартные поля ввода.
- **Tabs:** Панели с вкладками, рендерят лейаут через `renderLayout`.
| Класс | Назначение | getValue() |
|---|---|---|
| `TextBox` | Текстовое поле | Для `showSelectionButton` → `rawValue` (FK ID); для `isDate` → ISO `"yyyy-mm-dd"` или `null`; иначе → `getText()` |
| `MultilineTextBox` | Многострочное поле | `getText()` |
| `CheckBox` | Флажок | `getChecked()` → `boolean` |
| `ComboBox` | Выпадающий список | `getText()` |
| `DatePicker` | Выбор даты | `getValue()` → `Date` |
| `Button` | Кнопка | N/A |
| `Group` | Группировка контролов | N/A |

### TextBox — режим даты (`isDate: true`)

Активируется свойством `isDate: true` (или через `renderItem case 'date':`). Реализует 1С 8.2–стиль редактирования даты в формате `дд.мм.гггг`.

**Внутренние поля (конструктор):**
```
_dd, _mm, _yyyy     — строки текущей даты (пустые = незаполнено)
_dateSection        — 0=день, 1=месяц, 2=год (активная секция курсора)
_dateBtn            — DOM-кнопка «▾» (календарь)
_calPopup           — DOM-элемент всплывающего календаря
_calOpen            — bool: открыт ли календарь
_calYear/_calMonth  — год/месяц, отображаемый в календаре
_calKeyCapture      — функция-обработчик capture-phase keyboard
```

**Дисплей:** Пустая дата — `"  .  .    "` (пробелы), заполненная — `"13.03.2026"`.

**Клавиатура (1С-стиль):**
| Клавиша | Действие |
|---|---|
| Цифры | Заполняют текущую секцию, автопереход при заполнении |
| `→` / `←` / `.` | Переключение секции |
| `Tab` / `Shift+Tab` | Следующая секция → следующий контрол по DOM |
| `F4` | Открыть/закрыть всплывающий календарь |
| `Escape` | Закрыть календарь (если открыт) / очистить дату |
| `Enter` | Закрыть календарь (если открыт) / подтвердить ввод |
| `Backspace`/`Del` | Очистить текущую секцию |

**Всплывающий календарь:**
- Стиль Win98 (синяя шапка с месяцем, taблица 7×N)
- Неделя начинается с Пн, названия месяцев на русском
- Подсветка: сегодняшняя дата — жёлтым, выбранная — синим
- Кнопка «Сегодня» в подвале
- `position:absolute`, `z-index:99999`, **фиксированный `width`** (не `min-width`!)
- CSS класс кнопки: `input-field-button` (Win98 raised, тот же что у кнопок «...» и «▾»)

**Keyboard capture (ВАЖНО):**  
При открытии календаря: `document.addEventListener('keydown', this._calKeyCapture, true)` (capture-phase).  
При закрытии/навигации: обязательно убрать старый и добавить новый listener.  
Цель: предотвратить получение формой Escape/Enter раньше чем popup.

**Регистрация в renderItem:**
```javascript
case 'date': {
    properties.isDate = true;
    createTextControl(TextBox);
    break;
}
```

**`destroy()` должен:** закрыть календарь, снять `_calKeyCapture`, обнулить `_dateBtn`/`_calPopup`.

### Стандартные диалоги
| Функция | Кнопки | API |
|---|---|---|
| `showAlert(msg, onOk)` | OK | Callback |
| `showConfirm(msg, onOk, onCancel)` | Да / Нет | Callback или `await` → `true`/`false` |

## 3. КОММУНИКАЦИЯ КЛИЕНТ-СЕРВЕР

### RPC
```
callServerMethod(appName, methodName, params)
  → POST /app/call { app, method, params }
  → invokeAppMethod(app, method, params, sessionID, cb, req, res)
  → appModule[methodName](params, sessionID, req, res)
```
Первый аргумент серверного метода — **один объект** `params`.

### Dataset (контекст между вызовами)
```javascript
// Сохранение:
const id = dataApp.storeDataset({ table: 'organizations', id: 42, ... });
// Получение:
const ds = dataApp.getDataset(id); // → { table, id, ... }
```

### uniRecordForm: серверные методы
| Метод | Параметры | Назначение |
|---|---|---|
| `getLayoutWithData` | `{ tableName, recordID }` | Генерирует layout + данные + datasetId |
| `generateFormSpec` | `(tableName, params)` | Строит layout из метаданных модели; при новой записи — pre-генерирует UID |
| `applyChanges` | `{ datasetId, changes }` | Извлекает таблицу/ID из dataset; делает UPDATE или CREATE в зависимости от флага `isNew` |

### uniRecordForm: pre-генерация UID для новых записей

**Проблема:** При открытии формы для новой записи (`recordID` не задан) UID присваивался только в момент сохранения (`Model.create`). Это не позволяло форме показывать UID до записи в БД.

**Решение (паттерн `isNew` + pre-generated UID):**

```
generateFormSpec (recordID не задан)
  → _util.generateUID(modelName)     — генерируем UID тем же алгоритмом, что и dbGateway
  → data[UID].value = effectiveRecordId  — вставляем в поле UID формы
  → dataApp.storeDataset({ id: effectiveRecordId, isNew: true, ... })
```

```
applyChanges
  → dsObj.isNew === true   → operation: 'create'
    changes.UID не задан   → changes = { UID: recordId, ...changes }  (подставляем pre-generated)
  → dsObj.isNew === false  → operation: 'update' (стандартный путь)
```

**Защита в `drive_root/dbGateway.js` executor:**
```javascript
if (!data.UID) {          // генерировать ТОЛЬКО если UID ещё не задан
    data.UID = util.generateUID(Model.name);
}
```
Если pre-generated UID передан в `data.UID` — он сохраняется без изменений.

**Ключевые принципы:**
- UID генерируется **один раз** на сервере при открытии формы, до записи в БД.
- Флаг `isNew: true` хранится в датасете и является единственным источником истины о статусе записи (новая/существующая). Не полагайся на наличие/отсутствие `recordId` в `applyChanges` — к этому моменту `id` в датасете уже заполнен.
- В БД запись НЕ создаётся при открытии формы — только при сохранении.

## 4. СИСТЕМА ПРИЛОЖЕНИЙ (MySpace)

### `window.MySpace`
| Метод | Назначение |
|---|---|
| `register(name, descriptor)` | Регистрация приложения |
| `open(name, params)` → `Promise<id>` | Открытие (для `allowMultipleInstances` — новый экземпляр) |
| `getInstance(id)` | Получение экземпляра по ID |
| `close(id)` | Вызывает `inst.destroy()`, удаляет из реестра |

**Миграции данных:**
Проект использует автоматическую синхронизацию SQLite через Sequelize. При изменении `db.json` фреймворк пытается изменить структуру таблиц. Изменения типов (например, `TINYINT` -> `BOOLEAN`) в SQLite являются нормальным процессом отображения и не считаются фатальной ошибкой, если схема в JSON соответствует коду.

### Экземпляр приложения (instance)
```javascript
{
    id: string,
    appName: string,
    form: DataForm,        // ссылка на форму
    onOpen(params): void,  // вызывается при открытии
    onAction(action, params): void,  // делегирует в appForm.doAction()
    destroy(): void        // очистка
}
```

### Два потока закрытия
| Действие | Что вызывается | Результат |
|---|---|---|
| Кнопка X / ESC | `Form.close()` → `destroy()` + удаление DOM + событие `form-destroyed` | Экземпляр остаётся в MySpace registry |
| `MySpace.close(id)` | `inst.destroy()` + удаление из registry | DOM не удаляется автоматически |

**Вывод:** Для реакции на закрытие формы пользователем — слушай событие `form-destroyed`, а не оборачивай `inst.destroy`.

## 5. СТИЛИ И LAYOUT (style.css, WIN95 STYLE)

Система использует Flexbox для управления пространством (см. [style.css](node_modules/my-old-space/drive_forms/resources/public/style.css)).
- `.ui-form-content`: Flex-контейнер (column) для элементов формы.
- `.ui-dynamictable`: Имеет `flex: 1 1 auto`, чтобы занимать свободное место.
- `.ui-group`: Группировка элементов (`horizontal` или `vertical`).

## 6. dbGateway — ЕДИНАЯ ТОЧКА ДОСТУПА К БД

### Назначение
Все операции чтения/записи бизнес-данных проходят через `dbGateway.execute()`. Это позволяет перехватывать, проверять, модифицировать или блокировать запросы на любом уровне.

### Архитектура (каскадные middleware)
```
ЗАПРОС → [APP middleware] → [FORMS middleware] → [ROOT middleware] → EXECUTOR (Sequelize) → РЕЗУЛЬТАТ
```

Три уровня middleware:
| Уровень | Файл | Назначение |
|---|---|---|
| `app` | Регистрируется в `server.js` приложения | Бизнес-логика конкретного приложения |
| `forms` | `drive_forms/dbGateway.js` | Проверки сессий, прав, общие для форм |
| `root` | `drive_root/dbGateway.js` | Системные проверки, аудит, rate-limiting |

### API

**`dbGateway.execute(request)`** — выполнить запрос к БД через цепочку middleware.

```javascript
const result = await dbGateway.execute({
    operation: 'read',              // 'read'|'findByPk'|'findOne'|'count'|'create'|'update'|'delete'
    table: 'organizations',         // имя таблицы (как в БД)
    where: { id: 5 },              // условия (опционально)
    data: { name: 'Test' },        // данные для create/update (опционально)
    options: {                      // опции Sequelize (опционально)
        order: [['name', 'ASC']],
        limit: 20,
        offset: 0,
        raw: true,
        transaction: t             // для транзакций
    },
    context: {                      // контекст вызова (опционально)
        sessionID: 'abc',
        userId: 42,
        appName: 'uniListForm'
    }
});
```

**`dbGateway.use(level, fn)`** — регистрация middleware.

```javascript
// Сигнатура middleware:
async function myMiddleware(request, next) {
    // Изменить request...
    const result = await next(request);  // передать дальше
    // Изменить result...
    return result;
}

dbGateway.use('app', myMiddleware);
```

### Executor (конечная точка)
Расположен в `drive_root/dbGateway.js`. Преобразует `request` в вызов Sequelize.

**Ключевые механизмы:**
1.  **Санитизация данных:** Перед сохранением (create/update) пустые строки `""` преобразуются в `null` для полей с внешними ключами (`references`).
2.  **Генерация UID:** Присваивает `UID` новым записям. В качестве ключа хэша всегда используется `Model.name`.
3.  **Security Layer (Access Control):** В слое `dbGateway` на уровне `app` реализована автоматическая фильтрация данных для всех операций чтения/обновления/удаления (кроме `admin`):
    - Если в таблице есть `userId`, записи фильтруются по ID текущего пользователя.
    - Если есть `organizationId` или `hotelId`, записи фильтруются по привязке пользователя к организациям (через `user_organizations`).
    - Настройки безопасности (поля и исключения) берутся из `app.config.json`.

| operation | Sequelize метод |
|---|---|
| `read` | `Model.findAll()` |
| `findByPk` | `Model.findByPk()` |
| `findOne` | `Model.findOne()` |
| `count` | `Model.count()` |
| `create` | `Model.create()` |
| `update` | `Model.update()` |
| `delete` | `Model.destroy()` |

### Инициализация
- `drive_root/init.js` → `require('./dbGateway')` (загружает ядро)
- `drive_forms/init.js` → `require('./dbGateway')` (регистрирует forms-middleware)
- Приложения регистрируют app-middleware в своём `server.js` или `init.js` по необходимости

### Что НЕ проходит через dbGateway
Системные операции (сессии, авторизация, миграции) пока используют прямые вызовы Sequelize: `getUserBySessionID`, `createNewUser`, `createGuestUser`, `loadDefaultValuesFromDB`.

## 7. ПРОЦЕСС МИГРАЦИИ БАЗЫ ДАННЫХ (createDB.js)

### Запуск
`index.js` спавнит `drive_root/db/createDB.js` как дочерний процесс. Весь вывод миграции идёт от дочернего процесса. Основной сервер стартует только после успешного завершения дочернего.

### Цепочка инициализации
```
1. collectAllModels()          → сырые JSON-дефиниции из всех источников (без UID)
2. mergeModelDefinitions()     → слияние дефиниций с разных уровней
3. triggerProjectEvent('onModelsPostCollect', { mergedModelsDef, ... })
   ├── node_modules/my-old-space/events_handler.js → onModelsPostCollect  (framework)
   └── ./events_handler.js (проект)                → onModelsPostCollect  (project)
      ← ЗДЕСЬ ИНЪЕКТИРУЕТСЯ UID в каждую def.fields перед sequelize.define
4. computeCreateOrder()        → топологическая сортировка по FK
5. sequelize.define() для каждой модели
6. Model.sync({ alter: true }) → DDL
7. Начальный сид defaultValues
8. triggerProjectEvent('onDatabasePostInit', { sequelize })
```

### triggerProjectEvent — порядок вызова обработчиков
```javascript
// Расположение в createDB.js:
const frameworkHandlerPath = path.resolve(__dirname, '../../events_handler.js');
// => node_modules/my-old-space/events_handler.js  (НЕ drive_root/events_handler.js!)

const projectHandlerPath = path.join(projectRoot, 'events_handler.js');
// => D:/prj/wonunger/events_handler.js
```
Сначала вызывается framework-обработчик, затем project-обработчик. Оба получают один и тот же объект `context` — мутации видны следующему обработчику.

**КРИТИЧНО:** project `events_handler.js` загружается через `require()` (CommonJS). Поэтому он ДОЛЖЕН экспортировать через `module.exports`, а не `export default` (ESM). Неверный синтаксис приводит к тому, что файл не загружается, `onModelsPostCollect` не вызывается и UID не инъектируется.

### Инъекция UID (onModelsPostCollect)
`collectAllModelDefs()` возвращает **сырые JSON-дефиниции без поля UID** — поле UID отсутствует в `db.json` специально (см. инструкции). Его необходимо вставить до `sequelize.define()`. Паттерн из project `events_handler.js`:
```javascript
for (const def of mergedModelsDef) {
    if (!def.fields) def.fields = {};
    // Убрать primaryKey у других полей
    for (const [name, fld] of Object.entries(def.fields)) {
        if (name !== 'UID' && fld && fld.primaryKey) delete fld.primaryKey;
    }
    // Добавить/нормализовать UID
    if (!def.fields.UID) {
        def.fields.UID = { type: "STRING", allowNull: false, primaryKey: true, defaultValue: "GENERATE_UID" };
    } else {
        Object.assign(def.fields.UID, { primaryKey: true, allowNull: false, type: "STRING" });
        if (!def.fields.UID.defaultValue) def.fields.UID.defaultValue = "GENERATE_UID";
    }
}
```

### computeCreateOrder — топологическая сортировка (алгоритм Кана)
Порядок создания таблиц вычисляется из FK-зависимостей. Два важных краевых случая:
- **Само-референция** (`FileSystem_Files.parentId → FileSystem_Files`): ребро пропускается (`referenced !== table`), иначе indegree никогда не падает до нуля.
- **Дублирующиеся FK на одну таблицу** (напр. `ownerId` + `userId` → `users`): ребро считается только один раз через `Set countedEdges`, иначе indegree завышен и таблица застревает в очереди.

### 9.6 Счета (Invoices)

Счёт формируется **после** бронирования и содержит снапшот цен на момент выставления. Изменение тарифов не влияет на уже выставленные счета.

#### `Invoices` — заголовок счёта

| Поле | Тип | Описание |
|---|---|---|

#### `InvoiceLines` — строки счёта (снапшот)

|---|---|---|

### 9.7 Паттерн `defaultValues.json`

Для предопределённых системных записей (с фиксированными UID) используется файл `apps/<app>/db/defaultValues.json`.

- Файл сканируется патчем в `node_modules/my-old-space/drive_root/db/createDB.js` при старте приложения.
- Записи вставляются только если их `UID` ещё нет в таблице (`findOrCreate`).
- Lookup в коде: `getDefaultValue(level, tableName, defaultValueId)`.
- Формат: объект, где ключ = имя таблицы (`"guest_types"`), значение = массив записей с полем `UID`.

                                         ├── BookingGuests ──→ GuestTypes
                                         └── BookingRoomServices ──→ Services
